Smart Meal Planner, stap voor stap uitgelegd

De code, de app en de UML zijn in het Engels (voor de prof); deze uitleg is in het Nederlands. Een JavaFX-app met drie tabbladen: een receptenboek, een weekplan (7 dagen × 4 momenten) en een boodschappenlijst die zichzelf uitrekent. Deze pagina legt uit wat we bouwen, in welke volgorde, en waarom elk patroon op die plek staat. Onderaan vind je alle code en de UML-bestanden.

De patronen, eenvoudig uitgelegd

Een design pattern is een bekende, beproefde oplossing voor een probleem dat vaak terugkomt. Zie het als een recept: je hoeft het wiel niet opnieuw uit te vinden. Per patroon: een vergelijking uit het dagelijks leven, het probleem, de oplossing, waar het zit, het mini-klassendiagram en een typische examenvraag.

MVC: Model, View, Controller verplicht

Zo moet je het zien: Een restaurant. De zaal (View) is wat de klant ziet. De ober (Controller) neemt de bestelling op en controleert ze. De keuken (Model) heeft alle ingrediënten en maakt het eten. De klant loopt nooit zelf de keuken in.

Welk probleem lost het op? Als je schermcode, regels en data door elkaar schrijft, wordt alles één grote knoop. Eén knop aanpassen breekt dan je berekening.

Hoe? Splits de app in drie lagen die elk één taak hebben. De View tekent en stuurt klikken door. De Controller zet een klik om in een opdracht voor het model. Het Model bewaart de data en roept "er is iets veranderd!" (PropertyChange). De View hoort dat en tekent opnieuw.

Waar in ons project? MainView = View, PlannerController = Controller, MealPlannerDB (+ WeekPlan, GroceryList, ...) = Model. Exact dezelfde opbouw als in lab 5 (View, Controller, Database met PropertyChangeSupport).

// Model: roept naar iedereen die luistert
pcs.firePropertyChange("plan", null, recipe);

// View: luistert en tekent opnieuw
model.addPropertyChangeListener(this);
public void propertyChange(PropertyChangeEvent evt) { refresh(); }

// View -> Controller bij een klik
combo.setOnAction(e -> controller.assignMeal(day, slot, combo.getValue()));
Examenvraag: Hoe weet de View dat er iets veranderd is, ook als hij het zelf niet veroorzaakte (bv. bij undo)?

De View is ingeschreven als PropertyChangeListener bij het model. Elke wijziging in het model (ook een undo via de CommandHistory) roept firePropertyChange, dus de View krijgt altijd een seintje en roept refresh().

Singleton (thread-safe) verplicht

Zo moet je het zien: Er is maar één koelkast in huis. Iedereen die iets nodig heeft, gaat naar dezelfde koelkast. Had iedereen zijn eigen koelkast, dan zou de ene niet weten wat de andere opgegeten heeft.

Welk probleem lost het op? Het weekplan, de recepten en de boodschappenlijst moeten overal dezelfde zijn. Twee kopieën zouden uit elkaar lopen.

Hoe? Maak de constructor private (niemand kan new doen) en geef één statische methode getInstance() die altijd hetzelfde object teruggeeft. Thread-safe met "double-checked locking": eerst snel kijken zonder slot, dan met slot (synchronized) nog eens kijken. volatile zorgt dat elke thread meteen het volledig gebouwde object ziet.

Waar in ons project? MealPlannerDB.getInstance(). In lab 3 deed je dit al met IdGenerator (daar met een "eager" instantie). Hier tonen we de luie (lazy), thread-safe versie.

private static volatile MealPlannerDB instance;
private MealPlannerDB() { reset(); }

public static MealPlannerDB getInstance() {
    if (instance == null) {                   // 1e check: snel
        synchronized (MealPlannerDB.class) {  // slot: één thread tegelijk
            if (instance == null) {           // 2e check: was iemand sneller?
                instance = new MealPlannerDB();
            }
        }
    }
    return instance;
}
Examenvraag: Waarom twee keer if (instance == null) en waarom volatile?

Twee threads kunnen tegelijk de eerste check passeren. De eerste neemt het slot en maakt het object. Zonder de tweede check zou de tweede thread, zodra hij het slot krijgt, nóg een object maken. volatile voorkomt dat een thread een half-gebouwd object ziet (de JVM mag anders instructies herschikken). De eerste check zorgt dat we niet elke keer moeten wachten op het slot (sneller).

Observer (in het model, los van MVC) verplicht

Zo moet je het zien: Een YouTube-abonnement. Het kanaal (Subject) houdt een lijst van abonnees bij. Komt er een nieuwe video, dan krijgt elke abonnee een melding. Het kanaal hoeft niet te weten wat de abonnee daarmee doet.

Welk probleem lost het op? De opdracht zegt: de boodschappenlijst wordt automatisch bijgewerkt als het plan verandert. Het weekplan mag daarvoor niet zelf de boodschappenlijst moeten kennen en besturen.

Hoe? Het subject (WeekPlan) heeft een lijst observers en methodes addObserver, removeObserver, notifyObservers. Elke observer implementeert de interface PlanObserver met één methode: onPlanChanged(plan).

Waar in ons project? WeekPlan (subject) → PlanObserver (interface) ← GroceryList (observer). Bij elke set(...) rekent de lijst zichzelf opnieuw uit. Dezelfde structuur als lab 3 (Subject/Observer, de veiling).

Het optellen zelf: elk ingrediënt krijgt een sleutel naam|eenheid (bv. pasta|g). Met map.merge(sleutel, item, GroceryItem::plus) worden gelijke sleutels opgeteld. Hoeveelheden zijn gewone ints en de eenheid kies je uit een dropdown (g, ml of piece), dus 100 g + 100 g = 200 g zonder omrekenen. Vinkjes "gekocht" blijven bewaard, en extra items zitten in een aparte lijst.
// Subject
public void set(String day, String slot, Recipe recipe) {
    meals.put(day + " " + slot, recipe);
    notifyObservers();                        // "er is iets veranderd!"
}
private void notifyObservers() {
    for (PlanObserver o : observers) o.onPlanChanged(this);
}

// Observer
public class GroceryList implements PlanObserver {
    public void onPlanChanged(WeekPlan plan) { /* alles opnieuw optellen */ }
}
Examenvraag: Waarom telt dit niet als de "MVC-observer"?

De MVC-observer gaat van model naar scherm (PropertyChange naar de View). Deze Observer zit volledig binnen het model: model-object naar model-object (WeekPlan → GroceryList). Hij zou ook werken zonder scherm, bv. in de unit tests. Een tweede observer (bv. calorieteller) toevoegen kan zonder WeekPlan aan te passen.

Builder (onze creational keuze) verplicht: 1 van 3

Zo moet je het zien: Een broodje bestellen bij de Subway. Je kiest stap voor stap: brood, beleg, saus, extra kaas. Pas op het einde zegt de verkoper "klaar" en krijg je het broodje. Hij controleert eerst of je wel brood gekozen hebt.

Welk probleem lost het op? Een recept heeft veel velden, waarvan sommige optioneel (beschrijving, tags) en een lijst ingrediënten. Een constructor met 5+ parameters is onleesbaar en foutgevoelig.

Hoe? Een aparte RecipeBuilder verzamelt de stukjes met methodes die this teruggeven (zodat je kunt "ketenen"). build() controleert alles (titel? minstens één ingrediënt?) en maakt dan pas het Recipe. Daarna verandert het recept niet meer (alleen getters, geen setters).

Waar in ons project? RecipeBuilder → Recipe. De controller gebruikt hem bij toevoegen en bewerken. In lab 4b deed je hetzelfde met PaletteBuilder.

Recipe pasta = new RecipeBuilder()
        .title("Pasta pomodoro")
        .ingredient("pasta", 100, "g")
        .ingredient("passata", 200, "ml")
        .tag("vegetarian")
        .build();      // gooit een fout als de titel leeg is of er geen ingrediënten zijn
Examenvraag: Waarom Builder en niet Factory Method?

Factory Method is handig als je moet kiezen welk soort object je maakt (bv. lab 4a: welk boomtype). Wij maken altijd hetzelfde soort object (een Recipe), maar met veel onderdelen die je stap voor stap invult. Daar is Builder voor. Bonus: tests worden heel kort, want je bouwt een recept in één regel.

Command (ons extra patroon, met undo/redo) extra (≥1 uit de lijst)

Zo moet je het zien: Een bestelbonnetje in de keuken. De ober schrijft de opdracht op een briefje (object) in plaats van zelf te koken. De briefjes worden op een stapel bewaard, dus je weet wat er gebeurd is en kunt het terugdraaien.

Welk probleem lost het op? Plannen is uitproberen: de gebruiker wil een wijziging kunnen ongedaan maken en opnieuw doen.

Hoe? Elke actie wordt een object met execute() en undo(). De invoker (CommandHistory) voert het uit en legt het op een undo-stapel. Undo haalt het eraf, roept undo() en legt het op de redo-stapel. Het command onthoudt zelf wat er vroeger stond (previous).

Waar in ons project? Client = PlannerController (maakt het command), Invoker = CommandHistory, Command = interface Command, ConcreteCommand = SetMealCommand, Receiver = MealPlannerDB (doet het echte werk).

public void execute() {
    previous = db.getMeal(day, slot);   // onthoud wat er stond
    db.setMeal(day, slot, recipe);
}
public void undo() { db.setMeal(day, slot, previous); }

// CommandHistory
public void run(Command c) { c.execute(); undoStack.push(c); redoStack.clear(); }
Examenvraag: Waarom wordt de redo-stapel gewist bij een nieuwe actie?

Redo betekent "doe opnieuw wat ik net ongedaan maakte". Doe je intussen iets nieuws, dan is de geschiedenis een andere weg ingeslagen en klopt die oude redo niet meer. Daarom ook: bij bewerken of verwijderen van een recept wissen we de hele geschiedenis, want oude commands verwijzen naar de oude versie van het recept.

Vragen voor de verdediging

Klik een vraag open om het antwoord te zien. Probeer eerst zelf.

Wat is het verschil tussen de Observer van MVC en jullie eigen Observer?

MVC: model → View via PropertyChange (scherm hertekenen). Eigen Observer: WeekPlan → GroceryList binnen het model (lijst herberekenen). De tweede werkt zelfs zonder scherm.

Pasta staat twee keer in het plan. Waar wordt dat dubbel geteld?

WeekPlan.plannedRecipes() geeft een List (geen Set), dus pasta zit er twee keer in. GroceryList.onPlanChanged loopt over elk ingrediënt en doet merge(...) met GroceryItem::plus.

Hoe blijven vinkjes staan als de lijst herberekend wordt?

Na het optellen kijkt onPlanChanged voor elk nieuw item of het oude item met dezelfde sleutel aangevinkt was. Zo ja, dan wordt het nieuwe item ook aangevinkt.

Wat gebeurt er als je een recept verwijdert dat in het plan staat?

MealPlannerDB.removeRecipe roept plan.replaceEverywhere(id, null): het recept verdwijnt uit elk moment, het plan verwittigt de lijst (die krimpt) en de undo-geschiedenis wordt gewist.

Wat onthoudt SetMealCommand om correct te kunnen undo'en?

Het veld previous: het recept dat er vóór execute() stond (of null). undo() zet dat terug.

Hoe test je een Singleton als die tussen tests blijft bestaan?

Met db.reset() in @BeforeEach. En de controller krijgt de DB via de constructor, zodat de test zelf bepaalt welk object gebruikt wordt.

Waarom heeft Recipe geen setters?

Zo kan na build() niemand het recept nog stiekem aanpassen (de builder heeft het al gecontroleerd). Bewerken = een nieuw recept bouwen met hetzelfde id.

Waar had Strategy kunnen passen?

Bij een knop "vul lege momenten automatisch": RandomFill, VegetarianFill, QuickFill als verwisselbare algoritmes achter één interface. Niet nodig, want Command is al ons extra patroon.

package be.uantwerpen.sd.project.model;

/** One line of a recipe, e.g. 100 g pasta. */
public class Ingredient {
    public static final String[] UNITS = {"g", "ml", "piece"};   // the choices in the unit dropdown

    private final String name;
    private final int amount;
    private final String unit;

    public Ingredient(String name, int amount, String unit) {
        name = name.trim().toLowerCase();               // "Pasta " and "pasta" are the same
        if (name.isEmpty() || amount <= 0) throw new IllegalArgumentException("Invalid ingredient: " + name);
        if (!java.util.List.of(UNITS).contains(unit)) throw new IllegalArgumentException("Unknown unit: " + unit);
        this.name = name;
        this.amount = amount;
        this.unit = unit;
    }

    public String getName() { return name; }
    public int getAmount() { return amount; }
    public String getUnit() { return unit; }

    @Override
    public String toString() { return amount + " " + unit + " " + name; }
}

package be.uantwerpen.sd.project.model;

import java.util.List;

/** A recipe. Create it with the RecipeBuilder. It does not change after it is built. */
public class Recipe {
    private final String id;
    private final String title;
    private final String description;
    private final int calories;   // kcal per serving
    private final List<Ingredient> ingredients;
    private final List<String> tags;

    // not "public": only the RecipeBuilder (same package) creates recipes
    Recipe(String id, String title, String description, int calories, List<Ingredient> ingredients, List<String> tags) {
        this.id = id;
        this.title = title;
        this.description = description;
        this.calories = calories;
        this.ingredients = ingredients;
        this.tags = tags;
    }

    public String getId() { return id; }
    public String getTitle() { return title; }
    public String getDescription() { return description; }
    public int getCalories() { return calories; }
    public List<Ingredient> getIngredients() { return ingredients; }
    public List<String> getTags() { return tags; }

    public boolean hasTag(String tag) { return tags.contains(tag.toLowerCase()); }

    @Override
    public String toString() { return title; }   // this is how ListView and ComboBox show the title
}

/**
 * BUILDER: builds a Recipe step by step.
 *   new RecipeBuilder().title("Pasta").calories(550).ingredient("pasta", 100, "g").tag("quick").build();
 */
public class RecipeBuilder {
    private String id = UUID.randomUUID().toString();
    private String title = "";
    private String description = "";
    private int calories;
    private final List<Ingredient> ingredients = new ArrayList<>();
    private final List<String> tags = new ArrayList<>();

    /** Only needed when editing: the recipe keeps its old id. */
    public RecipeBuilder id(String id) { this.id = id; return this; }

    public RecipeBuilder title(String title) { this.title = title.trim(); return this; }

    public RecipeBuilder description(String description) { this.description = description.trim(); return this; }

    public RecipeBuilder calories(int calories) {
        if (calories < 0) throw new IllegalArgumentException("Calories cannot be negative.");
        this.calories = calories;
        return this;
    }

    public RecipeBuilder ingredient(String name, int amount, String unit) {
        ingredients.add(new Ingredient(name, amount, unit));
        return this;
    }

    public RecipeBuilder tag(String tag) {
        String t = tag.trim().toLowerCase();
        if (!t.isEmpty() && !tags.contains(t)) tags.add(t);
        return this;
    }

    /** Checks everything and only then returns the recipe. */
    public Recipe build() {
        if (title.isEmpty()) throw new IllegalArgumentException("A recipe needs a title.");
        if (ingredients.isEmpty()) throw new IllegalArgumentException("A recipe needs at least one ingredient.");
        return new Recipe(id, title, description, calories, List.copyOf(ingredients), List.copyOf(tags));
    }
}

package be.uantwerpen.sd.project.model;

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

/**
 * The week plan: 7 days x 4 meals.
 * OBSERVER (subject): on every change it notifies its PlanObservers.
 */
public class WeekPlan {
    public static final String[] DAYS = {"Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday", "Sunday"};
    public static final String[] SLOTS = {"Breakfast", "Lunch", "Dinner", "Snack"};

    private final Map<String, Recipe> meals = new HashMap<>();   // key e.g. "Monday Dinner"
    private final List<PlanObserver> observers = new ArrayList<>();

    public Recipe get(String day, String slot) { return meals.get(day + " " + slot); }

    /** Puts a recipe on a meal. recipe == null means: remove the meal. */
    public void set(String day, String slot, Recipe recipe) {
        if (recipe == null) meals.remove(day + " " + slot);
        else meals.put(day + " " + slot, recipe);
        notifyObservers();
    }

    /** All planned recipes. A list, so pasta planned twice counts twice. */
    public List<Recipe> plannedRecipes() { return new ArrayList<>(meals.values()); }

    /** Total kcal of all meals planned on one day. */
    public int caloriesOn(String day) {
        int total = 0;
        for (String slot : SLOTS) {
            Recipe r = get(day, slot);
            if (r != null) total += r.getCalories();
        }
        return total;
    }

    /** After editing a recipe: put the new version everywhere (null = remove everywhere). */
    public void replaceEverywhere(String id, Recipe replacement) {
        for (String key : new ArrayList<>(meals.keySet())) {
            if (!meals.get(key).getId().equals(id)) continue;
            if (replacement == null) meals.remove(key);
            else meals.put(key, replacement);
        }
        notifyObservers();
    }

    public void addObserver(PlanObserver o) { observers.add(o); }

    public void removeObserver(PlanObserver o) { observers.remove(o); }

    private void notifyObservers() {
        for (PlanObserver o : observers) o.onPlanChanged(this);
    }
}

public class GroceryItem {
    private final String name;
    private final int amount;
    private final String unit;      // "g", "ml" or "piece"
    private final boolean manual;   // true = added by hand (extra)
    private boolean bought;

    public GroceryItem(String name, int amount, String unit, boolean manual) {
        this.name = name;
        this.amount = amount;
        this.unit = unit;
        this.manual = manual;
    }

    /** "pasta|g": same key = same line on the list. */
    public String key() { return name + "|" + unit; }

    /** 100 g pasta + 100 g pasta = 200 g pasta */
    public GroceryItem plus(GroceryItem other) { return new GroceryItem(name, amount + other.amount, unit, manual); }

    public void toggleBought() { bought = !bought; }

    public String getName() { return name; }
    public int getAmount() { return amount; }
    public String getUnit() { return unit; }
    public boolean isManual() { return manual; }
    public boolean isBought() { return bought; }

    @Override
    public String toString() {
        return amount + " " + unit + " " + name + (manual ? "  (extra)" : "");
    }

package be.uantwerpen.sd.project.model;

import java.util.*;

/**
 * The grocery list.
 * OBSERVER (observer): listens to the WeekPlan and recalculates itself.
 */
public class GroceryList implements PlanObserver {
    private final Map<String, GroceryItem> generated = new TreeMap<>(); // from the plan, alphabetical
    private final List<GroceryItem> extras = new ArrayList<>();         // added by hand

    @Override
    public void onPlanChanged(WeekPlan plan) {
        Map<String, GroceryItem> fresh = new TreeMap<>();
        for (Recipe recipe : plan.plannedRecipes()) {
            for (Ingredient i : recipe.getIngredients()) {
                GroceryItem item = new GroceryItem(i.getName(), i.getAmount(), i.getUnit(), false);
                fresh.merge(item.key(), item, GroceryItem::plus);   // same key? -> add up
            }
        }
        // keep the "bought" ticks for items that are still on the list
        for (GroceryItem item : fresh.values()) {
            GroceryItem old = generated.get(item.key());
            if (old != null && old.isBought()) item.toggleBought();
        }
        generated.clear();
        generated.putAll(fresh);
    }

    public void addExtra(String name, int amount, String unit) {
        if (name.isBlank() || amount <= 0) throw new IllegalArgumentException("Enter a name and an amount > 0.");
        extras.add(new GroceryItem(name.trim().toLowerCase(), amount, unit, true));
    }

    /** First the calculated items, then the extras. */
    public List<GroceryItem> items() {
        List<GroceryItem> all = new ArrayList<>(generated.values());
        all.addAll(extras);
        return all;
    }

    /** Total of an ingredient in its base unit (0 if it is not on the list). */
    public int amountOf(String name, String unit) {
        GroceryItem item = generated.get(name + "|" + unit);
        return item == null ? 0 : item.getAmount();
    }
}

public final class MealPlannerDB {

    private final PropertyChangeSupport pcs = new PropertyChangeSupport(this);

    private MealPlannerDB() { reset(); }               // private: nobody else can call "new"

    public static MealPlannerDB getInstance() {
        if (instance == null) {                         // 1st check: fast, without a lock
            synchronized (MealPlannerDB.class) {        // lock: only one thread at a time
                if (instance == null) {                 // 2nd check: maybe another thread was faster
                    instance = new MealPlannerDB();
                }
            }
        }
        return instance;
    }

    /** Clears everything. Useful for tests, because the singleton stays alive. */
    public void reset() {
        recipes.clear();
        plan = new WeekPlan();
        groceries = new GroceryList();
        plan.addObserver(groceries);                    // OBSERVER: the list follows the plan
        pcs.firePropertyChange("reset", null, null);
    }

package be.uantwerpen.sd.project.command;

import java.util.ArrayDeque;
import java.util.Deque;

/** COMMAND (invoker): runs commands and remembers them for undo/redo. */
public class CommandHistory {
    private final Deque<Command> undoStack = new ArrayDeque<>();
    private final Deque<Command> redoStack = new ArrayDeque<>();

    public void run(Command c) {
        c.execute();
        undoStack.push(c);
        redoStack.clear();            // new action -> the old "redo" no longer makes sense
    }

    public void undo() {
        if (undoStack.isEmpty()) return;
        Command c = undoStack.pop();
        c.undo();
        redoStack.push(c);
    }

    public void redo() {
        if (redoStack.isEmpty()) return;
        Command c = redoStack.pop();
        c.execute();
        undoStack.push(c);
    }

    public boolean canUndo() { return !undoStack.isEmpty(); }

    public boolean canRedo() { return !redoStack.isEmpty(); }

    public void clear() {
        undoStack.clear();
        redoStack.clear();
    }
}

            if (row[2].isBlank()) continue;                       // row without ingredient name

        VBox form = new VBox(8, header("Recipe"), title, description, header("Calories (kcal per serving)"), calories,

        description.setText(r == null ? "" : r.getDescription());
        calories.setText(r == null ? "" : String.valueOf(r.getCalories()));
        tags.setText(r == null ? "" : String.join(", ", r.getTags()));
        ingredientRows.getChildren().clear();
        if (r == null) addIngredientRow(null);                      // new recipe: one empty row
        else for (Ingredient i : r.getIngredients()) addIngredientRow(i);
    }

    private void addIngredientRow(Ingredient ingredient) {
        IngredientRow[] row = new IngredientRow[1];   // array trick: the lambda may refer to its own row
        row[0] = new IngredientRow(ingredient, () -> ingredientRows.getChildren().remove(row[0]));
        ingredientRows.getChildren().add(row[0]);
    }

        Recipe r = recipeList.getSelectionModel().getSelectedItem();

                if (d == 0) grid.add(header(slot), 0, s + 1);

                combo.setPrefWidth(120);
                combo.setOnAction(e -> {
                    if (!refreshing && combo.getValue() != model.getMeal(day, slot))
                        controller.assignMeal(day, slot, combo.getValue());
                });
                Button x = new Button("✕");
                x.setOnAction(e -> controller.clearMeal(day, slot));
                cells[d][s] = combo;
                grid.add(new HBox(2, combo, x), d + 1, s + 1);
            }
            dayTotals[d] = new Label();
            dayTotals[d].getStyleClass().add("kcal");
            grid.add(dayTotals[d], d + 1, 5);
        }
        grid.add(header("Total"), 0, 5);
        Button undo = new Button("↶ Undo");
        Button redo = new Button("↷ Redo");
        undo.setOnAction(e -> controller.undo());
        redo.setOnAction(e -> controller.redo());
        grid.getStyleClass().add("card");
        ScrollPane scroll = new ScrollPane(grid);
        VBox.setVgrow(scroll, Priority.ALWAYS);
        VBox root = new VBox(12, scroll, new HBox(8, undo, redo));
        root.setPadding(new Insets(12));
        return new Tab("Week plan", root);

    private Tab groceryTab() {
        TextField amount = new TextField();
        ComboBox<String> unit = new ComboBox<>();
        TextField name = new TextField();
        amount.setPromptText("amount");
        unit.getItems().setAll(Ingredient.UNITS);
        unit.setValue("piece");
        name.setPromptText("name, e.g. dish soap");
        Button add = new Button("Add extra");
        add.getStyleClass().add("primary");
        add.setOnAction(e -> safe(() -> {
            controller.addExtra(name.getText(), amount.getText(), unit.getValue());
            name.clear();
            amount.clear();
        }));
        groceryBox.getStyleClass().add("card");
        ScrollPane scroll = new ScrollPane(groceryBox);
        scroll.setFitToWidth(true);
        VBox.setVgrow(scroll, Priority.ALWAYS);
        VBox root = new VBox(12, header("Calculated automatically from your week plan"), scroll,
                new HBox(8, amount, unit, name, add));
        root.setPadding(new Insets(12));
        return new Tab("Groceries", root);
    }

    // ======================= redraw everything =======================
    private void refresh() {
        refreshing = true;
        recipeList.getItems().setAll(model.getRecipes());
        for (int d = 0; d < 7; d++) {
            for (int s = 0; s < 4; s++) {
                cells[d][s].getItems().setAll(model.getRecipes());
                cells[d][s].setValue(model.getMeal(WeekPlan.DAYS[d], WeekPlan.SLOTS[s]));
            }
            dayTotals[d].setText(model.caloriesOn(WeekPlan.DAYS[d]) + " kcal");
        }
        groceryBox.getChildren().clear();
        for (GroceryItem item : model.getGroceries()) {
            CheckBox box = new CheckBox(item.toString());
            box.setSelected(item.isBought());
            box.setOnAction(e -> controller.toggleBought(item));
            groceryBox.getChildren().add(box);
        }
        refreshing = false;
    }

    private static Label header(String text) {
        Label label = new Label(text);
        label.getStyleClass().add("header");
        return label;
    }

    /** Runs an action and shows invalid input as a pop-up instead of crashing. */
    private void safe(Runnable action) {
        try {
            action.run();
        } catch (IllegalArgumentException ex) {
            showError(ex.getMessage());
        }
    }

    private void showError(String message) { new Alert(Alert.AlertType.ERROR, message).showAndWait(); }
